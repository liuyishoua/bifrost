# 现货策略研究与手动交易工作台设计

## 目标与使用者

本应用供 Bifrost 的单一所有者学习加密资产现货市场、记录公开策略、用历史数据检验可量化规则，并把研究对象与自己的币安现货及链上资产放在同一工作台查看。首版允许所有者在币安现货账户中明确确认后手动下单。系统解释数据、信号、假设和实际订单状态；不把回测收益当成未来收益或把相关性写成涨跌原因。

成功体验：用户搜索主流币或山寨币，看到可用历史区间；选择策略和参数，读懂每笔模拟交易及成本；保存来源和研究笔记；连接币安账户与 MetaMask 地址并查看按来源分列的资产；最后可以在清楚预览和主动确认后提交一笔币安现货订单，并查看该订单在交易所的真实状态。

## 首版范围

- 作为 `bifrost/applications/crypto/` 下独立的 Python Web 应用接入 Bifrost。使用现有应用清单机制的 `app.yaml`，由 Bifrost 分配本机端口及独立入口，不改 Ticket 和 Douyin 的业务代码。应用仅监听回环地址，数据保存在被 Git 忽略的应用运行目录。
- 市场页从币安现货交易对目录搜索交易对，不把币种限定为 BTC、ETH。显示报价资产、交易状态、历史数据覆盖、缺口与交易活跃度；不允许对已下架或数据不足的区间给出有效回测。
- 策略实验室首批提供均线交叉、区间突破、定投和买入持有基准。策略卡用自然语言写清入场、离场、参数和限制；用户可保存策略来源链接、自己的解读、参数及回测记录。首版不执行从网页复制的任意 Python 代码，也不自动把文章推断为交易规则。
- 资产页合并展示币安现货余额与 MetaMask 地址的链上余额，保留来源、链 ID、代币合约地址、余额时间和计价来源。首批链为 Ethereum 主网与 BNB Smart Chain。钱包连接只读取地址，不请求签名交易或助记词。缺失可信价格的资产单列为“未计价”，汇总金额注明未计价资产数量；同名代币按链和合约地址区分。
- 交易页支持币安现货限价与市价买卖、当前订单列表、订单详情及取消未成交订单。每次真实提交由用户在预览页再次确认；策略和回测绝不直接调用真实下单接口。首版没有定时、信号触发或后台自动下单。

## 架构与边界

应用拆为市场数据、策略、回测账本、资产源、订单执行和 Web 界面六个模块。统一的 `MarketData` 接口返回带交易所、交易对、时间粒度、时区、完整性和来源的 K 线；统一的 `AssetSource` 返回余额及其来源；策略只产出带时间戳和理由的 `OrderIntent`，不持有 API 凭证。回测执行器消费 `OrderIntent` 和历史 K 线；真实执行器只消费经预检、预览、用户确认和风险检查后的手动 `OrderIntent`。未来接另一交易所或自动策略时，复用这些接口，但自动执行需独立设计并启用。

币安公有历史数据归档负责批量 K 线，币安官方 Python SDK 负责交易对目录、账户、测试订单、真实订单和状态查询。市场数据存储以交易所、市场类型、交易对、粒度及时间范围为键，并保留来源与校验信息。CSV 导入采用同一校验路径，字段、时区和交易对必须显式指定。币安 API 不可用或限流时，显示缓存时间和失败原因；不把过期余额或报价显示为当前值。

链上资产由 MetaMask Connect 取得用户选择的地址，也允许手工输入公开地址。链适配器用 web3.py 读取原生币和用户指定的 ERC-20/BEP-20 余额；首版以 Blockscout 多链 API 发现其他代币，按链 ID 1 和 56 查询。Blockscout 不可用时仅显示已验证的已知代币，并标出发现服务故障，绝不声称资产列表完整。价格适配器用按链与合约地址查询的 CoinGecko 价格；无法匹配时保持“未计价”。读取资产与 USD 计价分开；索引器或价格源失败时仍显示已知数量，但不得把未计价资产算作零。首版不把 NFT、流动性池份额、借贷债务或跨链桥在途资产计入可计价总额，并在界面标注这一边界。

TradingView Lightweight Charts 用于 K 线、信号和实际/模拟成交标记，并保留其许可要求的署名。逐笔成交账本由应用明确控制，以保证下一根 K 线成交、手续费和滑点规则可解释；MIT 许可的 `bt` 仅用于结果统计与基准对比，不决定成交。CCXT 可作为第二家交易所的候选适配层，首版不引入。

## 回测规则与结果

首版为现货、单交易对、无借贷、无做空的策略回测。所有时间统一为 UTC。信号只使用当前及更早的已收盘 K 线；最早在下一根 K 线开盘价按所设滑点模拟成交。买入不能超过可用模拟现金，卖出不能超过持币数量。手续费按成交金额计，参数和初始资金由用户设定。运行区间至少包含 100 根连续 K 线及该策略需要的预热区间；缺失、重复、逆序或异常 K 线拒绝该区间回测，不能自动补出虚构价格。定投按指定 UTC 周期触发，并在触发后的下一根 K 线成交；区间结束后到期而未成交的信号不补单。

结果显示策略总收益、最大回撤、交易次数、胜率、费用总额、与同区间买入持有的比较，以及逐笔 `信号时间 → 模拟成交时间 → 数量 → 价格 → 成本 → 余额`。区间达到 30 天才按实际秒数折算年化收益，否则隐藏该指标。每次结果保存数据版本、参数、费用假设和策略版本。对于历史长度短、成交稀疏或上市不久的山寨币，结果附数据覆盖与流动性提示。页面说明 OHLC K 线不能证明订单簿里的真实成交与滑点，回测结果只代表所列假设。

## 币安连接与真实手动订单

币安只读凭证与可交易凭证分开配置。页面录入后只传服务端；服务端在受保护的运行目录中加密保存，解密主密钥从部署环境提供，数据库、日志、浏览器响应、回测导出均不包含密钥。没有主密钥时可用公开研究功能，但不能保存凭证或下单。账户设置页显示密钥权限和最后一次同步状态，拒绝具备提现权限的交易密钥。真实交易默认关闭；所有者设置交易解锁口令及正数的单笔、单日名义金额上限后才能启用。Bifrost 应用不授予其他普通账号。每次交易确认都重新输入交易解锁口令；仅保存其带盐哈希，不保存口令明文。部署假设为一个 Bifrost 管理员账户，增加第二位管理员或授予普通账号之前必须先实现账户身份隔离。

订单流程：服务器读取交易所实时 `exchangeInfo` 过滤条件、当前余额和报价；校验交易对状态、价格步进、数量步进、最小/最大名义金额、可用余额以及用户配置的单笔与单日名义金额上限；调用币安测试下单接口；生成短时有效的预览，列出市场/限价、买卖、数量、报价、预计金额、可能滑点、费用和风险上限，费用和滑点均标为估计。用户显式确认后服务器再次校验预览有效期、余额及交易对规则，先持久化唯一 `clientOrderId` 与“准备提交”记录，再向币安发送一次真实订单，随后查询币安订单状态。重复点击或重复 HTTP 请求复用同一记录并只查询状态，不生成另一订单。取消订单同样需要明确的用户动作。应用不会从回测页或策略事件直接提交真实订单。

网络超时、币安 5xx 或执行状态未知时，本地订单标为“待核实”，用原 `clientOrderId` 查询交易所，不自动再提交。币安返回的部分成交、已成交、已取消和拒绝状态以交易所为准；本地记录保留请求摘要、时间、交易所订单号、状态更新与错误码，不记录凭证。页面区分“提交请求已发送”与“订单已成交”。停止应用时，未完成的真实订单查询与写入完成后才报告空闲；在途提交时拒绝由 Bifrost 停止。应用启动后先恢复待核实订单的只读状态查询。

## Bifrost 接入与访问

应用遵守现有 manifest 接入契约，在自己的入口下使用相对资源和 API 路径。Bifrost 网关逐请求鉴权和写请求来源检查是外层保护；应用自身对凭证设置、订单预览、确认和取消继续使用 CSRF 校验，真实提交与取消另验交易解锁口令。应用只供本人的 Bifrost 管理员账号使用；若未来向其他账号授权，必须先设计按身份隔离的凭证、资产与订单，不能复用首版共享数据目录。公网部署必须使用 Bifrost 的 HTTPS 入口，业务端口只绑定回环地址。审计记录凭证连接、交易启用/关闭、订单预览、提交、取消及状态核实；不记录 API 密钥或助记词，钱包地址在日志中脱敏。

应用提供 Bifrost 就绪和活动状态接口，收到 SIGTERM 时停止接收新写请求并等待在途订单操作结束。历史回测可中断并恢复页面，真实订单提交不能因页面断开而重发。

## 验收与测试

1. 不设置任何密钥时，用户能在 Bifrost 中打开工作台、搜索多个币安现货交易对、导入或获取历史数据并完成策略回测。
2. 固定测试数据证明信号不会读取未来 K 线、成交在下一根、手续费与滑点入账正确、买卖数量受现金和持仓约束；缺失或重复数据不能悄悄产生结果。
3. 使用模拟币安响应验证账户余额、权限检查、交易对过滤条件、测试下单、预览过期、单笔与单日上限、部分成交、取消、超时/5xx 后只查询不重发、以及进程停止时的在途订单保护。自动测试不得调用真实下单接口。
4. 使用模拟链上/索引器响应验证多链同名代币不混同、未计价资产单列、价格与余额时间可见、第三方失败不会把资产计为零。
5. 验证未登录、未授权、写请求跨站来源和 Bifrost 故障时应用不可通过公网入口操作；所有凭证和运行数据不进入 Git。真实账户联调仅在所有者自行提供交易密钥并逐笔确认时进行。

## 后续阶段

首版不包含永续合约、杠杆、自动下单、链上签名交易、舆论情绪归因或“聪明钱”身份判断。后续可逐项增加：更多交易所与链、模拟盘、策略规则编辑器、链上行为研究、自动执行。每一项都沿用数据来源与订单意图边界，增加对应风险与授权设计，不把公开策略直接接到真实订单。

## 依据与可复用组件

- [Binance Public Data](https://github.com/binance/binance-public-data) 提供公开历史现货 K 线与校验文件。
- [Binance Spot API](https://github.com/binance/binance-spot-api-docs/blob/master/rest-api_CN.md) 定义账户、测试下单、真实订单与查询；[交易过滤条件](https://github.com/binance/binance-spot-api-docs/blob/master/filters.md)定义价格、数量和名义金额限制。
- [Binance Python Connector](https://github.com/binance/binance-connector-python) 为 MIT 许可的官方 SDK；[CCXT](https://github.com/ccxt/ccxt) 为 MIT 许可的多交易所候选。
- [MetaMask Connect](https://github.com/MetaMask/connect-monorepo) 取代旧 SDK，许可证有非商业使用与署名限制；本项目当前亦为非商业使用，依赖引入时须保留相应声明。
- [web3.py](https://github.com/ethereum/web3.py)、[bt](https://github.com/pmorissette/bt) 和 [Lightweight Charts](https://github.com/tradingview/lightweight-charts) 分别提供链交互、回测统计与图表；图表需按许可保留 TradingView 署名。
- [Blockscout 多链 API](https://dev.blockscout.com/) 提供链上代币发现；[CoinGecko 链上代币价格接口](https://docs.coingecko.com/changelog/10122018)提供按链与合约地址的价格数据。两者均通过独立适配器调用，网络失败或覆盖不足时按上文降级。
